# Contributing

Thank you for helping make survey pretesting clearer and more reproducible.

1. Open an issue describing the user need, expected behavior, and an example questionnaire with no personal data.
2. Keep examples fictional or explicitly licensed for redistribution. Do not commit real profiles, keys, or student submissions.
3. Run `python3 -m pytest` before a pull request. Add a focused test when behavior changes.
4. Explain the survey assumption behind a new weight or statistic. Avoid presenting simulated frequencies as measured population estimates.
5. Include a screenshot for visible UI changes and update the relevant README section.

We prioritize questionnaire import, quota design, privacy-safe local workflows, and comparisons with actual pilot studies.
