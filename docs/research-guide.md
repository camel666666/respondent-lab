# Research use guide

Respondent Lab helps test a questionnaire before fieldwork. The built-in panel is fictional and its distributions reflect explicit scenario assumptions. Even when a profile is derived from a consenting real person, a generated response is a model prediction rather than an observation.

## Suggested classroom workflow

1. Write the research question and target population.
2. Record the sample quotas and every scenario weight used in the simulation.
3. Run several seeds and compare unstable questions.
4. Ask a small number of real participants to review unclear wording and missing answer choices.
5. Conduct real data collection if the assignment requires empirical findings.
6. In the final report, label generated data and real responses separately.

## What validation would require

For a real-person-derived profile, get a dated, revocable consent record covering profile fields, permitted question topics, model processing, retention, and possible sharing. Strip direct identifiers from the model prompt. Keep source records out of the public repository. Compare generated answers with fresh answers from the consenting participant on held-out questions, and report agreement by question type and group. Review aggregate calibration against a real pilot sample. A coherence review by a stronger model does not substitute for these checks.

## Example disclosure

> This pretest used Respondent Lab to generate simulated responses from a fictional or consented profile panel. The results explore questionnaire behavior and are not observations of human respondents. All reported counts, charts, and quotes in this section are synthetic.
