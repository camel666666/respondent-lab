# GitHub launch checklist

Repository name: `respondent-lab`

Suggested description: `Open-source synthetic respondent lab for survey pretesting, stratified sampling, and transparent reports.`

Suggested topics: `survey`, `questionnaire`, `synthetic-data`, `research-tools`, `education`, `python`, `survey-pretesting`, `open-source`.

## Release sequence

1. Run the offline demo and tests on a clean checkout.
2. Confirm `git status` contains no private profiles, raw source records, API keys, or generated reports.
3. Publish a public repository with the README, license, screenshot illustration, issue templates, and CI workflow.
4. Set the description, topics, website/demo link if a public demo is deployed, and enable Discussions if maintainers can answer questions.
5. Publish a short release with the exact version, what works, known limits, and one example questionnaire.
6. Share a short demo with student and research communities, invite feedback on actual course workflows, and iterate from issues.

## Suggested launch post

> I built Respondent Lab, an open-source tool for rehearsing surveys before fieldwork. It provides a 1,000-person fictional panel, student/working-adult quotas, four question types, transparent simulation assumptions, and a report you can inspect. The demo works offline. If you teach research methods or design questionnaires, I'd love feedback on which import and comparison features would help most. Simulated answers are clearly labeled and should never be presented as real fieldwork.

Stars cannot be promised or manufactured. The useful milestones are a clean first-run experience, real issue reports, reproducible examples, and contributors who return.
